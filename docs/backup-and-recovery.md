# Backup and recovery

The full-instance backup helper stops the selected Cookbook service, then copies the SQLite database, any SQLite WAL/journal sidecar, media, and federation private-key files into a versioned archive. It restarts the service if it was running. Use `./scripts/backup-compose.sh [private-directory]`; the default remains `./backups`. The archive is plaintext and contains account data, private recipes/media, and private signing keys. The helper restricts the directory and archive to the current user (no group/other permissions), but does not encrypt them. Store archives only in a user-approved, access-controlled and encrypted destination. Do not treat filesystem mode 0600 as encryption or off-host protection.

Version 3 archives include the active federation signing key and, if a rotation is staged, its pending key. A non-secret manifest records SHA-256 fingerprints for every archived data file (database, sidecars, media and keys), the database's federation-enabled/origin settings when those columns are present, and the archive format version. It also records the Go recovery verifier's version-1 Person actor manifest, including active and retired actors, even when the actor set is empty. The manifest binds the database and key files into the same consistency check, so accidental omission, replacement, or corruption is detected before restore. The checksum list and manifest are stored beside the data in the same archive without a MAC or signature; a maliciously rewritten archive can replace both and is not detected. Protect the archive as sensitive data.

Finalization and validation use the exact local image configured for the selected Compose service. The image must already be available locally and resolve to one immutable image ID; these steps do not build or pull an image. The Go verifier runs without network access in a read-only container with only a private database snapshot mounted. It opens an explicit database path without applying migrations. The snapshot contains the database and any matching WAL or rollback-journal file. SQLite may create a transient `-shm` file in that private directory; stale `-shm` files are not archived. Python validates archive structure, checksums and federation-key file framing, while Go owns Person actor schema, lifecycle and key-pair validation.

Older version 2 archives have no Person actor manifest. They are checked against an explicit empty actor set: recognized pre-v5 databases and v5 databases with no actors remain valid, while active or retired actor rows fail closed. Version 1 legacy database/media archives use the same actor check and still require the existing federation key-loss acknowledgement. That acknowledgement does not waive Person actor continuity. New version 3 archives require a valid embedded actor manifest.

The fingerprint is a hash of the exact private-key file bytes. The validator checks the PEM envelope and Base64 framing but does not parse the private-key structure or prove Ed25519 validity. A fingerprint is not the federation protocol `key_id` and cannot prove a database-to-key relationship: the current database does not store the local signing-key ID. Version 2 preserves the database and active/pending key files as one recovery set and verifies their recorded file fingerprints and database federation settings. The Go service validates the key when it starts. If a key is malformed, startup fails rather than silently replacing it.

Restore with `./scripts/restore-compose.sh /path/to/archive.tar.gz`. The restore helper resolves the local verifier image and validates archive member paths, types, duplicate names, permissions, per-image and total size limits, checksums, key-file presence, database federation settings and the recorded Person actor set before stopping the service. It then replaces the database, media and `/data/secrets` from the archive, checksums the extracted files, and verifies the staged database and matching sidecars against the actor manifest before marking restore successful or restarting the service. Restore does not create an automatic pre-restore backup. Make and protect a separate backup first if you need one; choose its destination explicitly. If extraction or post-extraction verification fails after shutdown, the service remains stopped for inspection.

Older database/media archives have no bundled federation keys. The validator can inspect their safe legacy layout, but the restore helper refuses them by default because key continuity cannot be established. To accept a federation identity change explicitly, run `./scripts/restore-compose.sh --accept-federation-key-loss /path/to/legacy-archive.tar.gz`. This clears the destination's old `/data/secrets`; when the service starts, it generates a new federation signing key. The database and media can be restored, but the old federation identity is not recovered. Peers may need their trust records updated. Do not use this option when continuity matters; recover the matching key custody through an independently maintained recovery process before restarting the service.

The user-facing recipe/cookbook export is a separate, owner-scoped content export. Portable `cookbook-export-v3` archives include each saved bookmark's exact local instance-and-recipe identity or remote object URI, plus its creation time. They do not embed bookmarked source content, images, access rights, or cached remote bodies. Import preserves those references as references: it does not attach them to newly imported recipe copies, fetch remote objects, or grant access. A foreign local instance identity remains unavailable on the current instance; a missing or unreadable source remains unavailable until the source exists and the account can read it.

Portable export version numbers describe the user-facing recipe/cookbook archive format. They are separate from the versioned full-instance recovery archive described above; portable export is not a substitute for a full-instance backup or restore.

These scripts support Podman Compose when available, and Docker Compose remains selectable with `COOKBOOK_COMPOSE_ENGINE=docker`. Set `COOKBOOK_COMPOSE_ENGINE=podman` to select Podman explicitly. They do not create containers or volumes beyond Compose's normal one-off helper container.
